# Decisions log

Choices the brief left open, one line of reasoning each. Newest milestone at the bottom.

## M1 — Scaffolding

| Decision | Reasoning |
|---|---|
| SQLAlchemy **2.1.x** (latest 2.x) | Same 2.0-style API the brief asks for; no reason to pin an older minor on a new project. |
| PostgreSQL **17** (compose + CI) | Current stable major supported by Railway's Postgres; same version everywhere avoids surprises. |
| Test DB via `TEST_DATABASE_URL` (compose locally, service container in CI), not testcontainers | Works identically on CI without Docker-in-Docker and is faster to start; one less dependency. |
| Test schema built by running Alembic migrations | A broken migration fails the test suite instead of the Railway deploy. |
| Test DB name must end in `_test` | The harness drops the `public` schema; the guard makes pointing it at a real DB impossible. |
| Per-test isolation: outer transaction + `join_transaction_mode="create_savepoint"` | Services keep their own `session.begin()` while every test still rolls back. |
| ORM models live in `app/models/` (not in the brief's layer list) | Shared by repositories and Alembic; putting them in `repositories/` would make migrations import query code. |
| Constraint naming convention on `Base.metadata` | Stable, reviewable autogenerated migration names. |
| JSON logging with stdlib `logging` (no structlog) | Needs are small (one formatter); avoids a dependency. |
| `/health` returns 503 when the DB check fails or exceeds 3 s | Railway's healthcheck then refuses to promote a broken deploy. |
| CORS allow-list empty by default | The client is a native app; browsers only need same-origin web pages we serve ourselves. |
| `DATABASE_URL` `postgres(ql)://` auto-rewritten to `postgresql+asyncpg://` | Railway injects plain URLs; this keeps the variable copy-paste-able. |
| Migrations run as a separate pre-deploy step, not in the container `CMD` | Avoids concurrent migrations when Railway runs several replicas. Compose runs them inline for convenience. |
| Host ports configurable (`POSTGRES_PORT`, `API_PORT`, default 5432 / 8000) | Dev machines often already use these ports. |
| `uv` pinned to 0.12.23 in Dockerfile and CI | Reproducible lockfile handling across environments. |
| Container runs as non-root user | Basic hardening at zero cost. |
| No Git LFS for now | Art is mostly procedural/shader-driven; revisit if binary assets grow. |
| No Unity job in CI yet | Unity CI needs a license secret; C# simulation vectors will run through a plain `dotnet test` project instead (M2). |

## M2 — Simulation

| Decision | Reasoning |
|---|---|
| PCG32 (XSH-RR), stream 54, one draw per spawned block | Tiny, well-specified, with published reference output to test both ports against. |
| Units: 10 000 per world unit, 60 Hz ticks, blocks as half-open integer spans | Spans (`lo..hi`) avoid halving odd sizes, so no division of negatives, where C# and Python differ. |
| Perfect window = `450 + speed / 2` units (not a fixed 450) | With a fixed window, a 60 Hz tick could skip the whole window at high speed; perfects would be luck, not skill. Found by the golden-vector bot. |
| Every 4th consecutive perfect regrows the block by 1500 units on the moving axis (capped at full size) | Rewards streaks without making long runs trivial. |
| Score = 1 per block + `min(combo, 5)` bonus per perfect | Bonus is visible and meaningful but capped so one long streak doesn't dwarf everything. |
| Taps < 6 ticks after a spawn are invalid; runs capped at 1 h | The client ignores such taps anyway; anything else is a forged input log. |
| Vectors generated by a deterministic bot, never edited by hand | A changed vector means a changed rule, visible in review. |
| C# tests are plain NUnit shared between Unity EditMode and `dotnet test` | Cross-language parity runs in CI without a Unity license. |

## M3–M6 — Backend

| Decision | Reasoning |
|---|---|
| One initial migration for the whole schema | Nothing deployed yet; one reviewed migration beats five that were never applied separately. |
| ORM models live in `app/models/` | Shared by repositories and Alembic (see M1). |
| UUID primary keys for users/runs/challenges | Unguessable run ids double as the "run token" the brief mentions (the row is bound to its user server-side). |
| Guest = device ID + 32-byte random device secret (SHA-256 stored) | Knowing a device ID alone must not take over an account. |
| Refresh tokens: opaque, hashed, rotated; reuse revokes the family | Standard theft detection; access tokens are 15-minute HS256 JWTs. |
| Google/Apple verification implemented on PyJWT + JWKS (no Google SDK) | One small verifier for both providers, fully testable with generated keys. |
| Linking an identity owned by another account → `409 identity_in_use`; client offers "switch account" | Never silently merges two progress histories. |
| Anti-cheat verdicts: `verified` (counts), `flagged` (≥50 blocks with ≥98% perfects, kept for review, not counted), `rejected` | Replay is authoritative; precision heuristics only flag, never silently ban. |
| Submission must arrive no faster than 80% of simulated time − 2 s after run start | Cheap check that blocks instant forged submissions. |
| Rewarded continues are trusted from the client (one per run, never in duels) | AdMob server-side verification can be added later; the cap bounds abuse. |
| Coins: `score // 5`, credited only for verified runs; double coins keyed by run id | Idempotent by construction. |
| Ledger idempotency key unique per user; purchases/daily require `Idempotency-Key` | Retries can never double-charge or double-pay. |
| Ledger append-only enforced by a trigger on UPDATE (DELETE allowed for account deletion) | Audit trail without blocking GDPR-style deletion. |
| Lock order: run → wallet → streak | No deadlocks between concurrent reward paths. |
| Friend code stored on `users` (no separate `friend_codes` table) | One code per user; a table would add a join and nothing else. |
| Friendship accepted implicitly when starting a challenge run | "Become friends by accepting a challenge" from the brief. |
| Ties do not win a duel | "Beat the score" means strictly higher. |
| Daily rewards 25/35/50/70/90/120/200, day 7+ stays at 200; missing a day resets | Escalating, simple to explain on screen. |
| Rate limiting in-memory, per IP, per app instance | Railway runs one instance; swap the counter store for Redis if scaled out. |
| Landing pages server-rendered with escaped f-strings, no template engine | Four small pages; explicit escaping is tested. |
| OG image: static 1200×630 PNG generated by a dependency-free script | Messaging apps don't render SVG; per-challenge images would need Pillow + fonts. |
| `railway.json` lives in `backend/` (service root directory = `/backend`) | Monorepo: the backend is one Railway service. |

## M7–M9 — Unity

| Decision | Reasoning |
|---|---|
| Unity 6000.5 (the Unity 6 release installed here), project settings from the bundled "Universal 3D" template | A tuned mobile URP asset (HDR on) instead of hand-written render-pipeline assets. |
| Everything (world, UI) built in code; the scene is empty; `App` boots via `RuntimeInitializeOnLoadMethod` | No hand-authored scene/prefab YAML; every piece is reviewable in a diff. |
| Assemblies: `StackIt.Core` and `StackIt.Client` (no engine refs, unit tested), `StackIt.Runtime`, `StackIt.Editor` | Testable logic stays out of MonoBehaviours. |
| Own tiny tween runner instead of DOTween | Needs are punch/fade only; no third-party asset to import. |
| Procedural audio (synthesized clips), no music | Superseded by the look & feel pass below. |
| Input via uGUI full-screen tap catcher + Input System UI module | One input path; Input System is the template's only active backend. |
| Simulation advanced on unscaled time; slow-motion only on game over | Visual effects can never change the run being verified. |
| Rival ghost uses height (blocks); friends list exposes `best_placed` | The marker is drawn at a height; score alone can't place it. |
| Recorder: always-on GPU capture at 30 fps → 720×1280 → async readback → native H.264 ring buffer (~18 s) → MP4 mux on export | No screen-recording permission; memory stays at a few MB of compressed samples. |
| Android encoder uses an input Surface drawn with `lockHardwareCanvas` | The GPU does RGBA→YUV conversion; no native C code needed. |
| End card rendered offscreen into the recorder target, paced in real time (2 s) | Android's surface encoder timestamps on arrival. |
| Clips are silent | Keeps the encoder simple; most sharers add music on TikTok/Instagram. |
| **2026-10-31: recorder and clips removed.** The challenge is shared as a PNG of the end card (`EndCardRenderer.SavePng`) | Owner: the video took long to make and added no value. Nothing records during play any more. The recorder rows above and H3 below are history. |
| Android Java as loose files in `Plugins/Android` + a manifest-only `.androidlib` | Loose Java compiles with Unity's classes; the manifest merge adds intent filters + FileProvider to Unity's own activity. |
| Native deps via EDM4U `StackItDependencies.xml` | EDM4U ships with the Google Mobile Ads plugin, which is required anyway. |
| AdMob adapter outside all asmdefs, behind `STACKIT_ADMOB`, registered through `AdsServiceRegistry` | Project compiles with or without the plugin, however the plugin is packaged. |
| Consent order: UMP → ATT → `MobileAds.Initialize` | Google's documented order; nothing loads before consent. |
| Interstitials: ≥3 runs and ≥90 s apart, never first session or after a record, only between runs | The brief's rules, tested in `AdPolicy`. |
| Device secret stored in PlayerPrefs | Acceptable for a game guest account; linking Google/Apple is the durable path. |
| UI strings: `Resources/StackIt/strings.csv` imported into the Localization "UI" table; CSV is also the runtime fallback | Translators edit one file; a test enforces en/es completeness and matching placeholders. |
| iOS Google Sign-In sends no nonce | The GoogleSignIn 7 flow used doesn't take one; Apple and Android flows do. |
| Unity code verified with `dotnet` compile checks against the editor's assemblies | No Unity license was available in this environment (see PLAN.md, verification status). |

## Look & feel pass — "the sky climbs with you"

Brief from the owner: like Stack by Ketchapp but more premium and juicy, calm, the family-chores app's
tactile style; free Google Fonts and free sound packs; must run well on an iPhone X / Galaxy A55.

| Decision | Reasoning |
|---|---|
| Pastel time-of-day sky (dawn → day → dusk → night by tower height); blocks a step deeper than the sky; lower stack fades into the horizon | One signature idea; replaces the neon-on-purple look, which read as cheap and generic. |
| Horizon fade done per block in `StackView`, not with Unity fog | Fog would also tint the sky quad, and fog shader variants can be stripped from mobile builds. |
| Bevelled block meshes (`ChamferBox`, in `StackIt.Client`) built at each block's real size, cached by size | The lit bevels make blocks read as solid objects; non-uniform scaling would stretch the bevels. Pure code, so winding/closure is unit tested. |
| Bloom and chromatic aberration removed; neutral tonemapping, faint vignette, exposure swell on combos | Calm, and cheap on mid-range GPUs. |
| UI: ink on paper (chores palette), Fredoka for numbers/titles, Nunito Sans for text, Material Symbols Rounded icons | Matches the chores app the owner likes; icons replace text-only buttons. |
| Buttons sink onto a darker lip when pressed (`Pressable`), with click + light haptic | Tactile feedback was the main thing the old flat buttons lacked. |
| Canvas matches width (1080 units) on phones, height on wider screens | Rows can no longer get narrower than designed (the old 50/50 match broke words on tall phones). |
| Fonts subset with fonttools (Latin + Latin-1 + punctuation; 26 icons) and baked by Setup Project into static TMP atlases | Small repo files; nothing rasterized at runtime; TTFs don't ship. Characters outside the subset fall back to TMP's default font. |
| Kenney CC0 samples for taps, landings, misses, rewards; synthesized marimba for the perfect chime on a pentatonic scale | Real recordings feel better than synth beeps; the pentatonic scale makes streaks musical (`Feel.PerfectSemitones`, tested). |
| Shop ids (`synthwave`, `magma`, …) kept; only their looks changed | Renaming would need a data migration; names can change later. |
| UI strings in sentence case; eyebrows use an uppercase font style | Calmer voice; capitals stay a styling choice, not baked into translations. |

Third-party assets: Fredoka and Nunito Sans (SIL OFL 1.1), Material Symbols Rounded (Apache 2.0) in
`unity/Assets/_Project/Fonts` with their licences; Kenney "Interface Sounds" and "Impact Sounds" (CC0)
in `unity/Assets/_Project/Resources/StackIt/Audio` with the licence.

## Pop and Neon looks

Owner's spec: two themes, Pop (light pastel) and Neon (dark glow), switchable in Settings,
applied to every screen, the gameplay, the share end card and the web pages. Auto mode: every
judgment call is logged here. Supersedes the colour, font and UI-scale rows of the section above.

| Decision | Reasoning |
|---|---|
| Pure theme code in `Client/Theming` (engine-free, tested under .NET) rather than `Core` | `Core` is the deterministic simulation shared with the server; theming has no business there. |
| A 100-line JSON reader (`MiniJson`) instead of a library | `StackIt.Client` has no JSON dependency and only needs strings, numbers, lists and objects. |
| Unity and the backend each keep a byte-identical copy of `shared/theme/themes.json`, enforced by tests | Unity loads only from `Assets`, and the backend's Docker/Railway build context is `backend/`; changing deploy config was not worth it. |
| Extra tokens beyond the spec: `surface.sunken`, `surface.raised`, `surface.highlight(+Border)`, `toast.*`, `overlay.dim`, `medal.*`, `dot.ring`, `danger.onDanger`, `accent2.onAccent2`, `accent.glowPulse`, `block.emission`, `postFx.*` | Every visual difference between the looks is a token, so no screen branches on the look. |
| `accent` deepened (Pop `#19C9B4` → `#108274`, Neon `#2CF0D6` → `#188274`, edges ×0.68) with white `accent.onAccent`; the glows keep the spec's bright teal | Owner asked for bright text on the primary buttons; white needs ≥4.5:1 (it was 2.1 and 1.4), and small accent chips use the same pair. |
| `danger` adjusted: Pop `#D64545` → `#D34242`, Neon `#FF5C7A` → `#FF6886` | Minimal change to reach 4.5:1 for "Delete account" text on surfaces. |
| `surface.raised` (Neon `#12303A`) for modal cards and bottom sheets | Neon's 8% white surface let the 3D tower show through pause, daily and result sheets; renders confirmed it. |
| `ScreenSpaceOverlay` UI drawn by one SDF shader (`UIRoundedRect`) with all parameters in vertex data | Crisp at any size, one material so everything batches, and the glows survive in recorded clips (no bloom on UI). |
| Reference canvas 390 × 844, match 0.5, as specified | Replaces the 1080-wide width-match of the previous pass. |
| Default skin `classic` and sky `synthwave` follow the look (ramp, background); bought skins/skies keep their colours in both looks | Keeps shop ids and purchases intact; renamed both to "Classic". |
| Blocks unlit with exact face colours (`Block.shader`, by object-space normal) | The spec defines face colours; lit shading could not hit them. Neon adds emission for bloom. |
| Home hero: a four-block base, a ground shadow and the moving block sliding above it (attract mode) | Matches the reference images. |
| Pause menu added (pause icon on the HUD; auto-pause when the app loses focus) | Spec; the simulation simply stops ticking, so replays are unaffected. |
| Game over is one screen: "Continue" is a pill there; any other action ends the run first | The spec lists Continue among the result pills; the old two-step sheet had no primary button. |
| Pending challenges stored on the device (opened but not played) | The server has no challenge inbox; this drives the Friends section and dot without a backend change. |
| "New affordable skin" dot: unowned, affordable and not yet seen in the shop | The spec's dot needs a notion of "new"; kept locally. |
| Friend rows' "Challenge" starts a normal run with that friend as the ghost | Challenges are created from a finished run; this gives the row a useful action now. |
| Weekly reset countdown from the leaderboard's `since` + 7 days | The API already returns the period start. |
| Challenge code field takes 7 characters, not 6 | The backend issues 7-character codes (`CHALLENGE_CODE_LENGTH`). |
| Baked TMP font atlases are generated and git-ignored, rebuilt when their recipe (TTFs, characters, settings) changes | Larger atlases for the full Latin-1 set would add ~16 MB of YAML to the repo. |
| Icons: Material Symbols Rounded outline (FILL 0, wght 400, opsz 24 ≈ 2 px strokes) plus a filled cut for primary buttons | One consistent outline set, as specified. |
| Link previews rendered per challenge with Pillow (`/og/{code}.png`), cached | The spec asks for the score on the image; Pillow is the one new backend dependency. |
| App icons generated from the tokens (`scripts/generate_app_icons.py`); Neon is the store icon | An alternate Pop app icon needs native code on both platforms (iOS alternate icons, Android activity aliases): not simple, left out. |
| Music generated in code (`MusicPlan` + `MusicService`), G pentatonic like the perfect chime | Sped-up recordings change pitch; a scheduled sequencer changes tempo cleanly, and chimes land in key. |
| Reduce motion also skips the perfect-drop exposure/chromatic pulse | It is a flash; the spec's list (breathing, shake, glow pulses, slow motion) reads as "no movement or pulsing". |

## Monetization

| Decision | Reasoning |
|---|---|
| **Income comes from ads only. No real-money purchases, ever**: no IAP, coin packs, subscriptions or paid "remove ads" | Product decision (2026-10-23). Everything in the shop is bought with coins earned by playing. |
| Shop prices: earnable, "not too accessible but not too expensive" | Items should feel earned (a goal across several sessions) but never out of reach for a regular player. Calibrated with the run model and, after launch, with the wallet ledger (PLAN.md, "Measurement findings"). |

## Soundtracks

| Decision | Reasoning |
|---|---|
| Shop soundtracks are **built in code** like the default music: synthesized instruments, our own scores. No AI-generated or licensed audio. | Owner, 2026-10-24, to avoid legal risk: there are no service terms or training-data lawsuits involved, and nobody else can claim the music. It also keeps the tempo rising with the tower, the chime in key, and the download size near zero. Realistic instruments are best-effort; a stylized sound is acceptable (PLAN.md, "Soundtracks plan"). |
| Every style in G major or E minor | The perfect chime climbs G pentatonic, which fits both keys. |
| Synthesis in plain C# (`StackIt.Client.Music`), rendered off the main thread; `MusicService` only creates the clips and schedules notes | Testable under .NET; an offline renderer and a WAV preview tool hear exactly what the game plays; switching styles causes no hitch. |
| `VoicePool` (a free voice first, else the one ending soonest) replaces strict rotation, Classic included | The renderer found rotation cutting audible pad notes (8 in 4 bars of Classic at full intensity); now none in any style. The pool stays at 24 voices: 24 music + 8 effects = Unity's 32 real voices. |
| Genre styles start a run with their beat; bass at 10 blocks, full drive at 25 | Many runs end before 25 blocks, and a bought genre should be heard at once. Classic keeps 10 / 25 / 40. |
| A per-style `Level`, matched to Classic on phone-speaker loudness (bass below ~120 Hz ignored) | Switching soundtracks shouldn't jump in volume; raw loudness overrates the 808 and sub basses that phones can't play. |
| Effects baked into the clips, no Unity reverb or chorus filters | The WAV previews then match the game exactly. |
| Shop ids `music_*` | `classic` and `synthwave` were already block-skin and theme ids (one `skins` table, one id space). |
| The shop's listen button plays even with music switched off | The player asked to hear it; it ends after 10 s or on leaving the shop. |
| "Try for one run": a rewarded ad, then a run starts at once with that soundtrack | The ad is the player's choice (ads-only money rule) and the reward is used straight away. |
| No soundtrack list in Settings; equip in the shop | Same as skins and themes; Settings keeps the on/off switch. |
| Provisional prices: lo-fi 600, synthwave 800, reggaeton 1,000, K-pop style 1,000, metal 1,200 | Mid-to-upper shop range, a sink for engaged players (PLAN.md findings ▸ E). To revisit with real coin data. |

## Juice and near misses (H6 + H4)

| Decision | Reasoning |
|---|---|
| "Almost perfect" gets a banner and a light tap, no slow motion | Slowing the screen mid-run while the next block is already moving would feel wrong (the simulation runs on real time). |
| "Missed by X mm" is a toast, not a banner | The game-over sheet replaces the HUD right away; a toast stays on top of it. |
| Collapse only when the run is really over (`GameController.Finish`) | While Continue is on offer the tower must stay intact. |
| Fanfares stay in G pentatonic | Same rule as the chime and the music: never a clashing note. |

## Daily Tower, sharing and missions

| Decision | Reasoning |
|---|---|
| The daily seed is an HMAC of the UTC date with the server's JWT secret | Same for everyone, not guessable before the day, no table needed. |
| The daily board is friends only | Owner, 2026-10-24: no strangers' names, same as the other boards. |
| Daily runs pay coins like any run; unlimited attempts, the best counts | Wordle-style comparability without punishing practice; normal runs are unlimited anyway. |
| "Copy result" adds a duel link only for verified runs | Same rule as the Challenge button; an offline result is still copied. |
| H3 uses the recorder's existing "last N seconds" export | Starting on the best moment needed no native change; the run's banners caption the moment. |
| H5 without SDKs: TikTok by package intent (Android), Instagram Stories by its official intent / URL scheme; fall back to the sheet | Works with no keys and never strands the player. Share Kit (hashtag, green screen) needs TikTok registration first. |
| Missions computed from the day's verified runs; claims are ledger entries keyed `mission:<day>:<slot>` | No new table or migration; a claim can't pay twice, even when retried. |
| Mission rewards 20 / 30 / 45 + a 50-coin chest | At most 145 a day: a real boost for casual players (~120 a day today) without doubling engaged players' income. Provisional. |
| Mascot drawn with the block shader and look tokens | Matches every look and skin; no art pipeline yet. |

## Measurement (telemetry)

| Decision | Reasoning |
|---|---|
| First-party telemetry (`POST /v1/events` into Postgres), no analytics SDK | Joins with runs, wallet and challenges by `user_id`; no new third party or install size; we own the definitions (PLAN.md, "Measurement findings" ▸ H). |
| Event allow-list in `shared/telemetry/events.json`, enforced by the server | Unknown events or props are rejected and counted, so client bugs surface instead of polluting the data. Tests keep the backend copy and the C# names in sync. |
| Event ids generated on the device; insert `ON CONFLICT DO NOTHING` | A batch re-sent after a timeout or a crash is stored once. |
| `occurred_at` = client time within 7 days back / 5 minutes ahead, else server time | Offline-queued events keep their real day; broken or forged clocks can't move data around. |
| Session = foreground until background; back within 30 s continues it; full-screen ads never end it | Matches the usual definition; an Android ad pauses the app and would otherwise split sessions. |
| Revenue from AdMob `OnAdPaid` (impression-level, estimated) | Revenue per player and per placement in our own data; AdMob's console stays the payout source of truth. |
| Metric views in a separate `metrics` schema, applied by `scripts/metrics.py`, not by migrations | They are reports, not app schema: change them freely without a deploy or an Alembic revision. |
| Removed `com.unity.purchasing` and `com.unity.analytics` | No real-money purchases ever (Monetization); Unity IAP added the Play `BILLING` permission and billing library to the APK. |
