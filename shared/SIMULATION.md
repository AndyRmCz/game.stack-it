# Stack IT deterministic simulation (v1)

The client (C#, `unity/Assets/_Project/Scripts/Core`) and the server (Python,
`backend/app/domain/sim`) implement **exactly** these rules. Any change requires a new
`SIM_VERSION`, regenerated vectors, and both test suites green.

## Units and time

- Integer math only. Lengths are in **units**: `10_000 units = 1 world unit` (rendering divides).
- Time is in **ticks** at **60 Hz**. Tick 0 is the moment the run starts.
- No division or modulo is ever applied to a negative number (C# and Python round differently).

## PRNG: PCG32 (XSH-RR)

64-bit state, 64-bit increment, multiplier `6364136223846793005`. Seeding follows the reference
`pcg32_srandom_r(seed, 54)`:

```
state = 0; inc = (54 << 1) | 1
next(); state += seed; next()
next(): old = state; state = old * MULT + inc            (mod 2^64)
        xorshifted = ((old >> 18) ^ old) >> 27           (low 32 bits)
        rot = old >> 59
        return rotr32(xorshifted, rot)
```

Reference check: seed 42 → `a15c02b7 7b47f409 ba1d3330 83d2f293 bfa4784b cbed606e`.
The run seed is an unsigned 32-bit integer.

## Constants

| Name | Value | Meaning |
|---|---|---|
| `BLOCK_SIZE` | 30000 | Initial block width (X) and depth (Z) |
| `TRAVEL` | 45000 | Moving block offset range is `[-TRAVEL, +TRAVEL]` |
| `PERFECT_TOLERANCE` | 450 | Base perfect window; the effective window is `450 + speed / 2` |
| `SPEED_BASE` / `SPEED_RAMP` / `SPEED_MAX` | 900 / 12 / 2400 | Units per tick |
| `SPEED_JITTER` | 150 | Random extra speed in `[0, 150]` per block |
| `REGROW_EVERY` | 4 | Every 4th consecutive perfect regrows the block |
| `REGROW_HALF` | 750 | Regrow amount added to each side (capped at `BLOCK_SIZE`) |
| `COMBO_BONUS_CAP` | 5 | Max bonus points for one perfect |
| `MIN_TAP_GAP_TICKS` | 6 | A tap needs at least 6 ticks since the block spawned |
| `MAX_RUN_TICKS` | 216000 | 1 hour; later events are invalid |
| `MAX_CONTINUES` | 1 | 0 when continues are disabled (challenge runs) |

## State

- `top`: the current top block as half-open spans `x0..x1`, `z0..z1`.
  The base is `[-15000, 15000) x [-15000, 15000)`.
- `placed`: blocks placed so far (the base is not counted). Height = `placed`.
- Moving block: `axis`, `offset`, `dir` (+1/-1), `speed`, `spawn_tick`.
  The axis is **X when `placed` is even**, Z when odd. Its span on the moving axis is the top's
  span shifted by `offset`; on the other axis it equals the top's span.

## Spawning (once at tick 0, after every placement, after a continue)

At tick `T`: draw `r = next()`.
- `r & 1 == 0`: `offset = -TRAVEL, dir = +1`; otherwise `offset = +TRAVEL, dir = -1`.
- `speed = min(SPEED_BASE + SPEED_RAMP * placed, SPEED_MAX) + (r >> 1) % (SPEED_JITTER + 1)`.
- `spawn_tick = tick = T`.

## Advancing

Each tick: `offset += dir * speed`. If `offset > TRAVEL`: `offset = 2*TRAVEL - offset, dir = -1`.
If `offset < -TRAVEL`: `offset = -2*TRAVEL - offset, dir = +1`.
`advance_to(t)` applies this `t - tick` times.

## Input events

An ordered list of `{"t": tick, "type": "tap" | "continue"}`. Ticks never decrease.

Validation order (first failure wins): `unknown_event`, `run_too_long` (`t > MAX_RUN_TICKS`),
`events_out_of_order` (`t < tick`), then the per-type checks below.

**Tap at `t`** (phase must be `playing`, `t >= spawn_tick + MIN_TAP_GAP_TICKS`): advance to `t`, then
with `size` = top's length on the moving axis:
- `abs(offset) <= PERFECT_TOLERANCE + speed / 2` → **perfect** (the window is wider than one
  tick of travel, so every pass has a tick inside it; `speed` is positive so `/` is safe): the new block equals the top (offset 0).
  `combo += 1`, `perfects += 1`. If `combo % REGROW_EVERY == 0`: on the moving axis
  `lo -= REGROW_HALF; hi += REGROW_HALF`, then if `hi - lo > BLOCK_SIZE`: `hi = lo + BLOCK_SIZE`.
- else if `abs(offset) >= size` → **miss**: phase becomes `awaiting_continue`, `combo = 0`.
- else → **slice**: the new span is `[max(lo + offset, lo), min(hi + offset, hi))`, `combo = 0`.

On perfect/slice: `placed += 1`, `gained = 1 + (perfect ? min(combo, COMBO_BONUS_CAP) : 0)`,
`score += gained`, the new block becomes `top`, `max_combo = max(max_combo, combo)`, spawn at `t`.

**Continue at `t`** (phase must be `awaiting_continue`, `continues_used < MAX_CONTINUES`):
`continues_used += 1`, phase becomes `playing`, the missed block is discarded (top unchanged), spawn at `t`.

A run **ends** when the last event is a miss (phase `awaiting_continue`).

## Errors (rejected runs)

`events_out_of_order`, `tap_too_early`, `event_after_game_over`, `continue_without_miss`,
`continue_not_allowed`, `run_too_long`, `unknown_event`.

## Golden vectors

`shared/sim-vectors/*.json`, generated by `backend/scripts/generate_sim_vectors.py`:

```json
{
  "name": "...", "description": "...", "sim_version": 1,
  "seed": 42, "continues_allowed": true,
  "events": [{"t": 50, "type": "tap"}],
  "expected": {
    "error": null,
    "steps": [{"kind": "place", "n": 1, "t": 50, "axis": "x", "offset": -1200, "x0": 0, "x1": 0, "z0": 0, "z1": 0,
               "perfect": false, "combo": 0, "gained": 1, "score": 1}],
    "final": {"score": 1, "placed": 1, "perfects": 0, "max_combo": 0, "continues_used": 0,
              "ended": false, "tick": 50}
  }
}
```

`steps[].kind` is `place`, `miss` (no span fields) or `continue`. When `error` is set, `steps`
and `final` are omitted.
